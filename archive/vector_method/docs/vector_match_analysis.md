# Vector Match 算法详细分析文档

## 1. 概述

### 1.1 算法定位

Vector Match 是天文图像 plate solving 的**粗匹配**算法，用于在已知近似中心坐标和焦距信息的条件下，求解图像与世界坐标系之间的几何变换关系。它作为 plate solving 流水线的第一步（Step 1），输出中心坐标、旋转角、像素尺度、翻转模式等参数，供后续精匹配步骤使用。

### 1.2 核心思想

将图像检测星点和星表（Gaia）参考星分别构建为以各自中心为原点的二维向量组，在角秒空间中求解两组向量间的**相似变换**（旋转 + 统一缩放 + 平移），从而一次性解出：
- 中心坐标偏移（平移量 → ΔRA, ΔDec）
- 旋转角
- 像素尺度修正因子
- 翻转模式（4种）

### 1.3 与旧算法的根本区别

| 特性 | 旧算法（三角形匹配） | 新算法（向量组对齐） |
|------|---------------------|---------------------|
| 匹配单元 | 三角形（3点确定） | 向量对（2点确定） |
| 变换模型 | 仿射6参数 | 相似变换4参数 |
| 翻转处理 | 三角形天然旋转不变，需额外处理 | 4种翻转模式显式枚举 |
| 对离群点 | 敏感（1个错误三角形影响大） | RANSAC天然鲁棒 |
| 计算复杂度 | O(N³) 构建三角形 | O(N²) KDTree候选 |
| 参数约束 | 无缩放约束 | s ∈ [0.9, 1.1] 物理约束 |

## 2. 坐标系统与约定

### 2.1 天球坐标系

- **赤经（RA）**：向东增加，范围 [0°, 360°)
- **赤纬（Dec）**：向北增加，范围 [-90°, +90°]
- **Gnomonic 投影约定**：
  - ξ（xi）：东向偏移，对应 RA 增加方向
  - η（eta）：北向偏移，对应 Dec 增加方向

### 2.2 图像坐标系

- **像素坐标**：(x, y)，x 向右增加，y **向下**增加（FITS/CCD 标准）
- **图像中心**：(cx, cy) = (width/2, height/2)

### 2.3 关键约定：Y轴翻转

**图像像素 Y 向下，天球 Dec 向上**，两者方向相反。在构建图像向量组时，Y 分量必须取反：

```
ux = (x - cx) × s0      # X方向：图像右 = 天球东，方向一致
uy = -(y - cy) × s0     # Y方向：图像下 = 天球南，取反后方向一致
```

**如果不做 Y 翻转**：图像向量组与星表向量组的 Y 方向相反，RANSAC 无法找到正确的相似变换。实测中，不做 Y 翻转时所有4种模式均返回0内点。

### 2.4 角秒空间

所有向量组统一在**角秒空间**操作，而非像素空间。原因：
1. 消除像素尺度 s0 的先验误差影响（s0 通过缩放因子 s 修正）
2. 图像向量和星表向量在角秒空间中尺度一致，便于 RANSAC 搜索
3. 内点距离阈值 τ 可以用角秒直接设定，物理意义明确

## 3. 算法流程详解

### 3.1 Step 1：像素尺度与FOV计算

**输入**：焦距 focal_length_mm，像元尺寸 pixel_size_um，图像宽高 width × height

**计算**：

```
s0 = 206.265 × pixel_size_um / focal_length_mm    # 角秒/像素
FOV_diag = sqrt(width² + height²) × s0 / 3600.0   # 度
radius_deg = FOV_diag × 1.2 / 2.0                  # Gaia查询半径
```

**常数 206.265 的来源**：

1 弧度 = 180/π 度 = (180/π) × 3600 角秒 ≈ 206264.8 角秒

```
s0 = (pixel_size_um / 1000) / focal_length_mm × 206264.8  # mm→角秒
   ≈ 206.265 × pixel_size_um / focal_length_mm
```

**查询半径扩大1.2倍**：确保即使初始中心坐标有偏移，星表仍能覆盖图像实际视场。

### 3.2 Step 2：亮星选取策略

**图像侧**：

```
if n_saturated >= 10:
    N_img = n_saturated           # 仅用饱和星
    selected = all_saturated_stars
else:
    N_img = 100                   # 饱和+亮星共100颗
    selected = saturated + top_(100-n_sat)_brightest_normal_stars
```

**设计理由**：
- 饱和星质心稳定（信噪比极高），是最佳匹配候选
- 10颗是经验阈值：≥10颗饱和星已足够 RANSAC 求解
- 不足10颗时补充亮星到100颗，保证匹配可靠性

**星表侧**：

```
N_gaia = ceil(1.5 × N_img)    # 目标星数
```

1.5倍冗余的原因：
- 图像侧部分亮星可能不在 Gaia 数据库中（变星、双星等）
- 星表侧部分星可能因饱和而在图像中无法精确定位
- RANSAC 需要足够的候选对应来抵抗离群点

### 3.3 Step 3：极限星等二分法

**目标**：找到极限星等 G_mag_limit，使 Gaia 查询返回的星数 ≈ N_gaia

**算法**：

```
mag_low = 6.0, mag_high = 22.0
target_high = N_gaia × 1.1

for up to 30 iterations:
    mid = (mag_low + mag_high) / 2
    count = gaia_cone_search(center, radius, mag_limit=mid)
    if count < N_gaia:
        mag_low = mid          # 星太少，放宽星等
    elif count > target_high:
        mag_high = mid         # 星太多，收紧星等
    else:
        break                  # 星数在 [N_gaia, 1.1×N_gaia] 内
    if mag_high - mag_low <= 0.1:
        break                  # 收敛
```

**收敛性分析**：星等-星数关系在银道面附近近似指数增长，二分法通常在8-12次迭代内收敛。

### 3.4 Step 4：向量组构建

#### 3.4.1 图像向量组 U

```
cx = width / 2, cy = height / 2

对每颗选中的亮星 i:
    ux_i = (x_i - cx) × s0        # 角秒，X方向
    uy_i = -(y_i - cy) × s0       # 角秒，Y方向取反

U = {(ux_1, uy_1), (ux_2, uy_2), ..., (ux_N, uy_N)}
```

**物理含义**：U[i] 表示第 i 颗亮星相对于图像中心的天球角距离（角秒），Y 取反后与天球 convention 一致。

**数值范围**：以 4500×3600、s0=6.188 为例：
- X 范围：[-13923, +13923] 角秒 ≈ [-3.87, +3.87] 度
- Y 范围：[-11139, +11139] 角秒 ≈ [-3.09, +3.09] 度

#### 3.4.2 星表向量组 W

```
对每颗 Gaia 星 j:
    (ξ_j, η_j) = gnomonic_forward(α_j, δ_j, α_0, δ_0)    # 角秒

W = {(ξ_1, η_1), (ξ_2, η_2), ..., (ξ_M, η_M)}
```

**Gnomonic 投影公式**（标准 TAN 投影）：

```
Δα = α_j - α_0
cosc = sin(δ_0)×sin(δ_j) + cos(δ_0)×cos(δ_j)×cos(Δα)

ξ = cos(δ_j)×sin(Δα) / cosc × (180/π×3600)     # 角秒
η = (cos(δ_0)×sin(δ_j) - sin(δ_0)×cos(δ_j)×cos(Δα)) / cosc × (180/π×3600)
```

**有效性检查**：cosc > 1e-10（排除对径点，实际天文图像中不会出现）

### 3.5 Step 5：4种翻转模式

对星表向量组 W 施加4种坐标翻转预处理：

| 模式 | 二进制 | x处理 | y处理 | 物理含义 |
|------|--------|-------|-------|---------|
| 0 | 00 | 原样 | 原样 | 正常方向 |
| 1 | 01 | 取反 | 原样 | 东西镜像 |
| 2 | 10 | 原样 | 取反 | 南北镜像 |
| 3 | 11 | 取反 | 取反 | 中心对称 |

**实现**：

```
Wf = W.copy()
if mode & 1: Wf[:, 0] = -Wf[:, 0]    # x翻转
if mode & 2: Wf[:, 1] = -Wf[:, 1]    # y翻转
```

**为什么翻转在星表侧而非图像侧**：
- 翻转是星表到图像的映射关系，等价于对星表坐标做预处理
- 这样 RANSAC 中的旋转矩阵 R 始终满足 det(R) > 0（纯旋转），简化求解
- 4种模式独立运行 RANSAC，选最佳

### 3.6 Step 6：两阶段 RANSAC

#### 3.6.1 为什么需要两阶段

**设计文档中的原始方案**：从 U 和 W' 中各随机选2点，形成假设的2对匹配。

**问题**：U 和 W' 的索引没有对应关系！U[i] 和 W'[j] 不一定对应同一天体。从 N=163 个 U 点和 M=259 个 W' 点中独立随机选2对，正确配对的概率为：

```
P(正确) = (N_correct / (N×M))² ≈ (72 / (163×259))² ≈ 8×10⁻⁶
```

200次迭代中命中正确配对的概率 ≈ 1 - (1-8×10⁻⁶)^200 ≈ 0.16%，几乎不可能。

**解决方案**：先用 KDTree 建立候选对应关系，再在候选对上做 RANSAC。

#### 3.6.2 阶段1：KDTree 候选对应

```
对 U 中每个点 u_i，在 W' 中找最近邻 w'_j
如果 dist(u_i, w'_j) < candidate_radius:
    记录候选对 (i, j)
```

**candidate_radius 的选取**：
- 默认值：max(300, τ_coarse × 20) 角秒
- 物理含义：允许初始中心偏移约 300 角秒 ≈ 0.083 度
- 实测银心区域：89 对候选对应（U=163, W'=259, radius=309角秒）

**为什么候选半径可以很大**：
- 候选对应只是"可能"的匹配，包含大量错误配对
- RANSAC 的作用就是从这些候选中筛选出正确的子集
- 候选半径越大，正确配对被包含的概率越高，但错误配对也越多
- RANSAC 的鲁棒性可以处理高达 70% 的离群率

#### 3.6.3 阶段2：RANSAC 采样与求解

**相似变换模型**：u = s × R(θ) × w' + t

4个参数：
- s：缩放因子（理想≈1.0）
- θ：旋转角（弧度）
- tx, ty：平移量（角秒）

**2点采样求解**：

从 P 个候选对中随机选2对 (pi, pj)：

```
u_a = U[pairs[pi].u_idx], w'_a = W'[pairs[pi].w_idx]
u_b = U[pairs[pj].u_idx], w'_b = W'[pairs[pj].w_idx]

# 缩放因子
s = ‖u_a - u_b‖ / ‖w'_a - w'_b‖
if s ∉ [0.9, 1.1]: 丢弃此假设

# 旋转角
θ = atan2(u_a - u_b) - atan2(w'_a - w'_b)

# 平移量
t = u_a - s × R(θ) × w'_a
```

**缩放因子约束 s ∈ [0.9, 1.1] 的物理依据**：
- s0 的误差主要来自焦距标称值与实际值的偏差
- 消费级望远镜焦距误差通常 <5%，专业级 <2%
- 0.9~1.1 的范围覆盖了 ±10% 的焦距误差，留有充足余量
- 此约束大幅减少无效假设，加速 RANSAC 收敛

#### 3.6.4 内点统计（1对1互斥匹配）

```
1. 将相似变换应用到整个 W'：û_j = s × R(θ) × w'_j + t
2. 构建 KDTree(û)
3. 对 U 中每个点找 û 中最近邻，记录距离 d_i
4. 按距离升序排列，贪心分配：
   - 如果 d_i < τ 且 û 的对应星未被占用 → 标记为内点
   - 否则跳过
5. 统计内点数 n_inliers 和 RMS
```

**1对1互斥**：确保每个图像星点最多匹配一个星表星点，避免多对一匹配导致虚假高分。

**贪心策略**：按距离升序处理，距离小的优先匹配。这保证了最近邻匹配的全局最优性（在贪心意义下）。

#### 3.6.5 RANSAC 参数

| 参数 | 值 | 说明 |
|------|-----|------|
| K（最大迭代） | 500 | 候选对数 P 的组合上限 min(500, P×(P-1)/2) |
| τ_coarse | max(1.0, 2.5×s0) | 粗匹配内点阈值（角秒） |
| τ_fine | max(0.5, 1.0×s0) | 精化内点阈值（角秒） |
| min_inliers | max(5, 0.2×N_img) | 最少内点数 |
| candidate_radius | max(300, τ_coarse×20) | 候选对应搜索半径（角秒） |

**τ 的自适应设定**：τ 与像素尺度 s0 挂钩，确保 τ ≈ 2.5 像素（粗）或 1.0 像素（精化）。

### 3.7 Step 7：Coarse-to-Fine 精化

**动机**：粗匹配用较大的 τ（≈2.5像素），很多"近似正确"的匹配被算作内点，导致 RMS 偏高。精化用更小的 τ（≈1.0像素），只保留精确匹配。

**精化流程**：

```
1. 用粗匹配的内点建立精确对应关系
   - 对内点 U_in，在变换后的 W't 中找最近邻
   - 形成 (u, w') 对应对 pairs_arr

2. 在 pairs_arr 上重新运行 RANSAC（300次迭代，τ_fine）
   - 从 pairs_arr 中随机选2对
   - 求解相似变换
   - 用 τ_fine 统计内点
   - 记录最佳变换

3. 如果精化后内点数 ≥ min_inliers，替换粗匹配结果
```

**为什么在内点上重新 RANSAC 而非直接用最小二乘**：
- 内点集中仍可能包含错误匹配（粗 τ 较大时）
- RANSAC 可以进一步过滤这些错误匹配
- 最小二乘会被离群点拉偏

**实测效果**：

| 阶段 | 内点数 | RMS |
|------|--------|-----|
| 粗匹配（τ=15.47″） | 85 | 6.41″ (1.04px) |
| 精化（τ=6.19″） | 74 | 3.90″ (0.63px) |

### 3.8 Step 8：打分与模式选择

**单模式内打分**：

```
score = n_inliers - λ × RMS    (λ = 1.0)
```

- 内点数多、RMS 小 → 得分高
- λ = 1.0 表示1个额外内点可以容忍1角秒的 RMS 增加

**跨模式归一化打分**：

```
score_norm = (n_inliers / min(N_img, M)) × (1 - RMS / τ)
```

- 第一项：内点率，归一化到 [0, 1]
- 第二项：精度率，归一化到 [0, 1]（RMS=0 时为1，RMS=τ 时为0）
- 综合得分范围 [0, 1]

**模式选择**：选归一化得分最高者。若最高得分 < 0.15，判定匹配失败。

**失败阈值从 0.3 降到 0.15 的原因**：实测中正确匹配的归一化得分约 0.28-0.34，而错误匹配通常 < 0.05。0.15 提供了足够的裕量。

### 3.9 Step 9：WCS 参数提取

#### 3.9.1 中心坐标修正

```
ΔRA  = tx / (cos(δ₀) × 3600)    # 角秒→度，考虑赤纬处的赤经收缩
ΔDec = ty / 3600                  # 角秒→度

α_c = α₀ + ΔRA
δ_c = δ₀ + ΔDec
```

**赤经收缩因子 cos(δ₀)**：赤经是角度而非弧长，在赤纬 δ₀ 处，1度赤经对应的实际弧长为 cos(δ₀) × 1度。因此将角秒偏移转换为赤经度数时需要除以 cos(δ₀)。

#### 3.9.2 旋转角提取

```
θ = atan2(sin_θ, cos_θ)    # 从 R 矩阵元素提取
```

其中 R 矩阵为：

```
R = [[cos_θ, -sin_θ],
     [sin_θ,  cos_θ]]
```

#### 3.9.3 最终像素尺度

```
s_final = s0 × s
```

s 是 RANSAC 求解的缩放因子，修正了 s0 的先验误差。

#### 3.9.4 仿射6参数

```
a0 = tx,            b0 = ty
a1 = s × cos_θ,     b1 = s × sin_θ
a2 = -s × sin_θ,    b2 = s × cos_θ
```

仿射变换将星表向量（角秒，已翻转）映射到图像向量（角秒，Y向上）：

```
u = a0 + a1 × w'_x + a2 × w'_y
v = b0 + b1 × w'_x + b2 × w'_y
```

### 3.10 Step 10：中心修正 + 精化

**流程**：

```
1. 用平移量修正中心坐标
2. 以新中心重新 gnomonic 投影 Gaia 星
3. 施加翻转模式
4. 用 τ_fine 重新运行 RANSAC
5. 如果找到更好的变换，更新结果
```

**为什么只做一次而非迭代**：
- 实测发现迭代重投影会导致偏移量累积发散
- 原因：中心修正后重新投影改变了向量组的形状，RANSAC 可能找到不同的（错误的）匹配
- 单次修正已经将中心精度提高到亚角秒级别，足够粗匹配使用

## 4. 天球坐标→像素坐标投影

### 4.1 完整投影流程

给定 Gaia 星的天球坐标 (α, δ) 和 VectorMatchResult，投影到像素坐标：

```python
# Step 1: Gnomonic 投影到角秒偏移（以 result.center 为原点）
xi, eta, valid = gnomonic_forward(alpha, delta, result.center_ra, result.center_dec)

# Step 2: 施加翻转模式
W = np.column_stack([xi[valid], eta[valid]])
Wf = _apply_flip(W, result.flip_mode)

# Step 3: 用仿射参数映射到图像向量空间（角秒，Y向上）
u = a0 + a1 * Wf[:, 0] + a2 * Wf[:, 1]
v = b0 + b1 * Wf[:, 0] + b2 * Wf[:, 1]

# Step 4: 图像向量→像素坐标
px = u / s0 + width / 2
py = -v / s0 + height / 2    # Y 取反
```

### 4.2 关键注意事项

1. **翻转必须在投影前施加**：仿射参数 (a0,...,b2) 是在翻转后的星表向量 Wf 上拟合的，投影时必须先翻转再映射
2. **Y 取反**：图像向量 Y 向上（天球 convention），像素 Y 向下，转换时需取反
3. **s0 是初始像素尺度**：除以 s0 将角秒偏移转换回像素偏移

### 4.3 投影精度验证

实测（银心区域，163饱和星，259 Gaia星）：

| 距离阈值 | 星数 | 占比 |
|----------|------|------|
| < 1 px | 217 | 46.9% |
| < 2 px | 264 | 57.0% |
| < 5 px | 311 | 67.2% |
| > 10 px | 137 | 29.6% |

> 10px 的星主要是暗星（Gaia 有记录但图像上太暗或检测不到），属于正常现象。

## 5. 数据结构

### 5.1 VectorMatchResult

```python
@dataclass
class VectorMatchResult:
    center_ra: float          # 修正后的中心赤经（度）
    center_dec: float         # 修正后的中心赤纬（度）
    rotation_deg: float       # 旋转角（度）
    scale_arcsec_px: float    # 最终像素尺度（角秒/像素）
    flip_mode: int            # 翻转模式 (0-3)
    matched_count: int        # 匹配内点数
    rms_px: float             # RMS（像素）
    rms_arcsec: float         # RMS（角秒）
    affine: tuple             # 仿射6参数 (a0,a1,a2,b0,b1,b2)
```

### 5.2 仿射参数的物理含义

```
u = a0 + a1×w'_x + a2×w'_y    # 图像X向量（角秒，东向）
v = b0 + b1×w'_x + b2×w'_y    # 图像Y向量（角秒，北向）
```

| 参数 | 公式 | 含义 |
|------|------|------|
| a0 | tx | X方向中心偏移（角秒） |
| a1 | s×cos(θ) | X缩放+旋转 |

## 7. 算法复杂度分析

### 7.1 时间复杂度

| 步骤 | 复杂度 | 实测耗时 |
|------|--------|---------|
| 星点检测 | O(W×H) | 16.7s |
| Gaia查询 | O(log N) | <0.1s |
| 向量组构建 | O(N+M) | <0.01s |
| KDTree候选对应 | O(N×log M) | <0.01s |
| RANSAC主循环 | O(K×(N+M)) | ~0.5s |
| Coarse-to-fine | O(300×(N+M)) | ~0.3s |
| 中心修正+精化 | O(K×(N+M)) | ~0.5s |
| **总计（不含检测）** | | **~1.3s** |

### 7.2 空间复杂度

- 向量组 U：O(N_img) ≈ 163 × 2 × 8 bytes ≈ 2.6 KB
- 向量组 W：O(M) ≈ 259 × 2 × 8 bytes ≈ 4.1 KB
- KDTree：O(M) 构建，O(N) 查询
- 候选对：O(min(N,M)) ≈ 89 对

内存占用极小，主要瓶颈在星点检测和 Gaia 查询。

## 8. 参数敏感性分析

### 8.1 candidate_radius

| 候选半径 | 候选对数 | 粗匹配内点 | RMS |
|----------|---------|-----------|-----|
| 77″ | 89 | 85 | 1.04px |
| 309″ | 89 | 101 | 1.37px |
| 600″ | ~200 | 102 | 1.49px |

较大的候选半径增加候选对数，但也引入更多噪声。309″（默认值）是较好的平衡。

### 8.2 τ（内点阈值）

| τ | 含义 | 内点数 | RMS |
|---|------|--------|-----|
| τ_coarse=15.47″ | 2.5px | 101 | 1.37px |
| τ_fine=6.19″ | 1.0px | 74 | 0.63px |

Coarse-to-fine 策略有效：先用大 τ 找到初始变换，再用小 τ 精化。

### 8.3 K（迭代次数）

| K | 粗匹配内点 | 备注 |
|---|-----------|------|
| 200 | 85 | 偶尔漏掉最优解 |
| 500 | 85 | 稳定找到最优解 |

500次迭代足够覆盖候选对的组合空间。

## 9. 已知限制与改进方向

### 9.1 当前限制

1. **初始中心偏差限制**：查询半径 1.2×FOV_diag/2，如果初始中心偏差超过此范围，星表将缺少对应星
2. **迭代重投影发散**：中心修正后重新 RANSAC 可能找到不同匹配，导致偏移累积
3. **仅相似变换**：无法处理镜头畸变（需要仿射或更高阶变换）
4. **暗星投影偏差大**：Gaia 有记录但图像上检测不到的星，投影位置可能偏离

### 9.2 改进方向

1. **自适应 candidate_radius**：根据初始中心偏差估计值调整
2. **迭代重投影稳定性**：在精化阶段固定内点集，只更新变换参数
3. **仿射变换精化**：在相似变换收敛后，切换到6参数仿射变换处理畸变
4. **多图像联合求解**：利用同一晚的多幅图像联合约束变换参数

## 10. 与设计文档的偏差

| 设计文档 | 实际实现 | 原因 |
|----------|---------|------|
| 纯随机2点采样 | KDTree候选+RANSAC | 纯随机正确配对概率≈8×10⁻⁶ |
| K=200 | K=500 | 候选对数增多，需要更多迭代 |
| τ=1.5″ 固定 | τ_coarse=2.5×s0, τ_fine=1.0×s0 | 自适应+coarse-to-fine |
| 迭代重投影收敛 | 单次中心修正+精化 | 迭代重投影发散 |
| 失败阈值0.3 | 0.15 | 实测正确匹配得分0.28-0.34 |
| min_inliers=0.3×N_img | 0.2×N_img | 银心区域饱和星多但匹配率偏低 |
