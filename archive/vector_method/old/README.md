## 1. star_alignment/ — 旧版星点对齐模块

**用途**: 第一步粗匹配，使用KDTree+sigma-clip直接匹配

**核心算法**:
- 三阶段匹配：粗拟合(相似变换) → 仿射精拟合 → 二次畸变拟合
- 饱和星优先策略：饱和≥10用全部饱和星，<10用饱和+亮星共100颗
- KDTree匹配替代三角形匹配（WCS近似正确假设下可靠）

**测试结果**:
- RMS: 0.931px ✅（<1px目标达成）
- 匹配数: 5043对
- 耗时: 0.14s

**归档原因**: 代码结构混乱，缺少4翻转模式独立测试，与siril算法差异大

**关键文件**:
- `psm_star_alignment.cpp/h` — C++实现
- `psm_star_alignment.dll` — 编译产物
- `siril_flow_analysis.md` — siril算法分析文档

## 2. initial_wcs_v1/ — 初始WCS模块v1

**用途**: 完整重写的初始WCS生成模块，参考siril atpmatch/Valdes 1995

**核心算法**:
- Step1: 像素尺度/FOV计算（206.265 × pixel / focal）
- Step2: Gaia锥形查询 + 极限星等二分法
- Step3: Gnomonic投影（RA/Dec → xi/eta → pixel）
- Step4: 饱和星优先三角匹配（ba/ca空间，radius=0.002）
- Step5: 4种翻转模式独立匹配 + 选择最佳
- Step6: 全星点验证匹配（递减半径50→30→10→2）
- Step7: 迭代重投影收敛（siril风格）

**测试结果**:
- RMS: 21.7px ❌（目标<2px）
- 匹配数: 754对 ✅（>100）
- 翻转模式: 2（Y翻转）— 错误，应为0（正常）
- scale报告: 0.9996 arcsec/px — 错误，应为6.188

**失败原因分析**:

1. **三角匹配完全失败**:
   - `AT_TRIANGLE_RADIUS=0.002` 是siril归一化坐标下的匹配半径
   - 我们的坐标是像素坐标，ba/ca值范围0.5~1.0，差异~0.05远超0.002
   - siril原始代码有坐标归一化步骤，我们缺少

2. **KDTree回退RMS过高**:
   - 使用全部星点（14000×21000）在5px半径下匹配
   - 随机匹配概率：P ≈ π×5²×14000×21000/(4500×3600)² ≈ 1400个假匹配
   - 这些假匹配导致RMS=21.7px

3. **翻转模式检测错误**:
   - 4模式独立测试都使用KDTree回退（三角匹配失败）
   - KDTree从identity transform开始，对翻转不敏感
   - 所有模式给出相似结果（~3.5px RMS），选择逻辑失效

4. **scale报告错误**:
   - 仿射变换在像素到像素坐标系下，a1≈1.0是正确的
   - 但结果中scale_arcsec_px应使用输入的像素尺度（6.188）
   - 代码错误地使用仿射线性部分模作为scale

**关键文件**:
- `initial_wcs.py` — Python原型（~1200行）
- `psm_initial_wcs.cpp/h` — C++实现（~600行）
- `psm_initial_wcs.dll` — 编译产物
- `initial_wcs_ctypes.py` — Python ctypes绑定
- `test_initial_wcs_e2e.py` — 端到端测试脚本

## 用户最新设计思路（2026-06-02）

**核心物理洞察**:
- 饱和星和排名靠前的亮星中，超过一半一定与Gaia最亮星一一对应
- 因为最亮的恒星在天空中是客观存在的，只要在FOV内就必然被观测到

**新算法方向**:
1. 以图像中心为坐标系中心，亮星坐标构成向量组
2. 向量长度换算到天球坐标系（使用文件头比例尺）
3. 以文件头中心坐标为中心，Gaia最亮星赤经赤纬为基，构建向量组
4. 两组向量组对齐，考虑四种翻转模式、缩放、旋转
5. 设计打分方法寻找最优变换矩阵
6. 从变换矩阵提取中心偏移量、缩放、旋转角、翻转等

**关键改进**:
- 利用文件头中的焦距和像元大小计算比例尺（精确已知）
- 向量组对齐替代三角/四边形特征匹配
- 打分方法处理无法匹配的向量（异常过滤）
